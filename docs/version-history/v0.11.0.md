## Purpose

Investigate whether generated ChatGPT images expose a reliable exact image-generation model identifier and, when they do, preserve that identifier in the offline export without guessing.

## User-visible changes

Generated-image captions can now show `Image model: <exact identifier>` when the conversation image metadata contains a safe, image-specific model field. When the provider does not expose an exact identifier, the caption uses `Image model: unknown / not found`. The existing message-model display preference controls whether image-model labels are shown. The individual-image chooser uses the same safe label when available.

## Diagnostic and privacy boundaries

The discovery helper inspects only bounded image-specific fields such as `image_model`, `imageModel`, `generation_model`, `generationModel`, and nested image-generation metadata. It accepts conservative model-identifier characters, rejects executable-looking or oversized values, and never infers an image model from the surrounding assistant model, filename, image appearance, prompt text, or the fact that an image was generated.

No image bytes, signed URLs, cookies, authorization headers, raw response bodies, conversation text, or full private identifiers are recorded. The implementation is local-only and does not add telemetry or third-party requests.

OpenAI’s public API documentation lets an API caller select an image model explicitly, while its provenance documentation describes C2PA as origin and AI-use metadata rather than a guaranteed model-name source. These public API facts do not prove that ChatGPT’s undocumented conversation endpoint exposes the same identifier.

## Limitations and decision

The current candidate does not claim that ChatGPT always exposes the model. The live test must determine whether the exact field appears in the user’s current account and image-generation flow. If it does not, the feature remains safe and useful by showing `unknown / not found` rather than inventing a model name.
