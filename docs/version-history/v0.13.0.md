## Purpose

Stop Claude exports silently losing edited prompts and regenerated replies.

## The defect

A live export taken on 2026-09-18 (`Greeting`, v0.12.0) carried two messages and this header:

```
Branches: 1 of 3 exported
Coverage: 3 dropped nodes, 0 duplicate messages removed
```

The conversation held five messages across three branches. The regenerated reply the product owner was looking at on screen was one of the three the export discarded. The failure is intermittent.

`orderedClaudeMessages` in `src/claude-client.mjs` selects the exported branch from a single field, `raw.current_leaf_message_uuid` — the pointer Claude's server keeps for the current branch. Claude's web client does not always push that pointer to the server at the moment a prompt is edited or a reply regenerated, so an export taken inside that window walks to a leaf one step behind the screen. Reloading the conversation resyncs the pointer, which is why the same steps sometimes produce a correct export.

The pointer is Claude's server state and cannot be corrected from a userscript. The fix removes the dependency on it instead.

## User-visible changes

**Every branch is exported by default.** The conversation-branch preference now defaults to `Include edited and regenerated branches`. Each fork point in the offline file carries the local `‹ 1/2 ›` controls already shipped in v0.10.0, so each version is reachable and the server pointer no longer decides what survives. The branch the pointer names is still rendered first.

**Existing installs move to the new default once.** Saved preferences carry a `prefsVersion`; a stored preference without one is upgraded to the new branch default and re-saved. A preference saved after the upgrade — including a deliberate return to `Export current branch only` — is left alone.

**Unexported branches are no longer reported as data loss.** The conversation-level `droppedNodeCount` for Claude previously counted every message not on the exported path, which surfaced as a yellow `Coverage: N dropped nodes` warning. On this provider every node is a real message, so nothing was structurally dropped; those messages were withheld by choice. Claude's `droppedNodeCount` is now `0` and a new `alternateBranchMessageCount` reports the withheld messages on a neutral line naming the setting that keeps them. The coverage warning still fires for genuine drops and duplicate removals.

## Behaviour deliberately unchanged

- Branch order: the branch named by `current_leaf_message_uuid` stays first and stays labelled active. Ranking leaves by `created_at` was rejected — it would fix the stale-pointer case and break the case where the owner deliberately switched back to an older version.
- No attempt is made to read the on-screen branch from the DOM or from browser storage. It is undocumented, breaks on every Claude redesign, and the all-branch default makes it unnecessary.
- The `Image model:` caption and `diagnostics/` are untouched, pending the open product decision.
- Claude attachments and uploaded images remain placeholder `[non-text content omitted]` markers. Image embedding is ChatGPT-only and was not in this release's scope.

## Known trade-off

All-branch exports are larger, and `resolveAllConversationBranches` resolves images per branch, so a heavily branched ChatGPT conversation with many images downloads more than before. The image chooser labels each entry with its branch, so the selection stays controllable. Revisit only if a real export feels slow.

## Follow-up

- Live acceptance: edit a prompt, regenerate the reply, then export **without reloading the page** — the case that fails today — and confirm every version is present and the arrows switch between them.
- Root-level forks (an edited opening prompt) render as consecutive turns rather than one switcher. Found in live testing of this release; fixed in v0.13.1.
- Claude uploaded images and attachments are still not embedded, only marked as omitted. Reported by the product owner on 2026-09-18; needs a scope decision and one live check of the Claude attachment payload shape before it can be planned.
- The `Image model:` decision remains open and blocks deleting `diagnostics/`.
