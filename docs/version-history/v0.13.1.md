## Purpose

Finish what v0.13.0 started. That release made every version survive the export; this one makes an edited opening prompt *read* as a set of versions rather than as extra turns.

## The defect

Live testing of v0.13.0 on a Claude conversation with an edited opening prompt produced a file listing four messages in a row — `hi 2`, its reply, `hi`, its reply — with a single `‹ 1/2 ›` control. Claude's own UI shows the same conversation as one prompt with a version switcher and one reply with another.

`renderBranchTree` in `src/core.mjs` attached fork controls only below a parent message:

```js
return tree.map(renderNode).join('\n');
```

A fork below a message was handled; a fork at the root list was not. Editing the very first prompt is exactly that case — the alternatives have no parent message to hang controls under — so they were emitted one after the other as if they were consecutive turns.

## Fix

The fork markup is factored out of `renderNode` into a `renderFork(children)` helper, used in both places:

```js
return tree.length > 1 ? renderFork(tree) : tree.map(renderNode).join('\n');
```

The root list with more than one entry is now a fork like any other, with the same `‹ n/m ›` switcher, the same active-branch detection via `containsActive`, and the same `data-fork-id` wiring the exported script already drives. Nothing was added to the offline runtime — `.branch-fork` / `.branch-choice` handling already generalises over every fork in the document.

This is provider-neutral: `branchTreeFromBranches` (ChatGPT) and `claudeBranchTreeFromBranches` (Claude) both produce multiple roots for a root-level edit, and both now render correctly.

## ChatGPT "Branch to a new chat"

Checked because the product owner asked whether OpenAI's branching change affects this exporter. It does not. The action, shipped in September 2025, creates a **separate conversation with its own ID** rather than a new branch inside the current tree; the original thread is untouched and the new one carries the context up to the branch point. The in-conversation version navigator for edits and regenerations is unchanged, and so is the `mapping` / `parent` / `current_node` shape this exporter reads. A branched chat exports like any other conversation.

Established from third-party reporting rather than from a live response inspection; no change was made on the strength of it.
