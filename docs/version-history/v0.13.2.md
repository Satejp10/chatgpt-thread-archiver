## Purpose

Two reading-order corrections found in live testing: a version switcher that did not say what it switched, and an uploaded image that arrived before the prompt it belonged to.

## Switcher placement

v0.13.1 gave a root-level fork its own `‹ 1/2 ›` control. Both controls were emitted after their alternatives, so a conversation with an edited prompt *and* a regenerated reply below it ended with two identical switchers stacked at the foot of the document and nothing to say which governed which.

`renderBranchTree` now emits the control before the options:

```js
return `<div class="branch-fork" data-fork-id="${forkId}">${controls}${options}</div>`;
```

Each switcher reads as the header of the block it belongs to — the prompt switcher above the prompt, the reply switcher above the replies. The offline script is unchanged; it selects by `data-fork-id` and never depended on document order. `.branch-choice` loses the `-8px` top margin that tucked it under the preceding card and takes a plain `0 0 12px` instead.

## Uploaded images and the prompt

ChatGPT sends an uploaded image as a content part **ahead** of the text it was sent with. The exporter copied that order faithfully, so a prompt with an attachment read image-first, which is the reverse of how the conversation was written and of how ChatGPT displays it.

`extractTextBlocks` now moves image blocks after non-image blocks **for user messages only**, and only when the message has both. Assistant messages keep provider order: there the text introduces the image that follows it, and reordering would break that. A user message carrying only an image is untouched.

## Claude uploads

Confirmed with the product owner: ChatGPT embedding works for both uploaded and generated images; Claude embeds neither, because it was never built. Claude has no image generation, so uploads are the whole of what support would mean there. Still unplanned — it needs a scope decision and one live look at Claude's attachment payload shape. Today those parts remain `[non-text content omitted: Claude attachment or file content]`.
