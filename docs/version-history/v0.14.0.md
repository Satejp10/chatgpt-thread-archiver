## Purpose

Claude exports now embed uploaded images. Until this release every image attached to a
Claude prompt came out as `[non-text content omitted: Claude attachment or file content]`.

## What the payload actually carries

Claude's conversation API is undocumented, so the field was established by running
`diagnostics/claude-attachment-probe-mini.js` on a live conversation on 2026-09-18 rather
than guessed. The probe reports structure only — field names, value types, redacted route
shapes — and its output showed:

- An uploaded image sits on `message.files[]` with `file_kind: "image"`.
- `preview_url` and `thumbnail_url` are same-origin routes of the shape
  `/api/<organization-id>/files/<file-id>/preview`.
- Both return image bytes directly to the signed-in session: `200`, `image/webp`.
- `preview_asset` / `thumbnail_asset` carry `image_width` and `image_height`.
- There is **no original-size route** in the payload. `preview` is the largest variant
  Claude exposes, so it is what the exporter embeds.

No private identifier, file name, URL or conversation content from that run was recorded
in this repository.

## Changes

**`src/claude-client.mjs`** — `normalizeClaudeMessage` turns each `files[]` entry with
`file_kind: "image"` and a `preview_url` into a real `image` block carrying the preview
route as its pointer plus the preview dimensions. `generated` is hard-coded `false` and
`imageModel` `null`: Claude has no image generation, so no Claude export can ever show an
image-model caption. Every other attachment — a PDF, a text file — keeps its omission
marker, because the payload still offers no fetchable representation of one.

**`src/chatgpt-assets.mjs` → `src/assets.mjs`** — the module is the image pipeline for
both providers now, so it no longer carries one provider's name. Selection, budget,
caching, per-occurrence results and the stats the header reports were already
provider-neutral; the only provider-specific step is turning one asset into bytes. That
step becomes an injected `resolveOne`, with `requiresAuth` alongside it so the Claude path
never mints or reads a bearer token — the session cookie carries the authorization.
`resolveClaudeConversationImages` is that pipeline with the Claude resolver.

The Claude resolver accepts **only** a `claude.ai` URL matching the confirmed file route,
`/api/<id>/files/<id>/(preview|thumbnail)`. A URL appearing anywhere else in the payload,
or on any other host, is refused rather than fetched.

**`src/exporter-ui.js`** — the image preferences stop being ChatGPT-only. Include all,
exclude all, and the per-image chooser now apply to Claude uploads on the same terms, and
`resolveAllConversationBranches` takes the resolver so an all-branches Claude export
resolves images per branch like ChatGPT already did.

## Known limitation

The chooser's size figures read high for Claude. `size_bytes` in the payload is the size
of the file the person uploaded; the exporter embeds the smaller preview variant. It is
the only size available before the bytes are fetched. The header's `KB embedded` figure,
counted after the fetch, is exact.

New coverage: the fixture reproduces the live shape, including a second non-image
attachment. Assertions check that a user message normalizes to `['text', 'image',
'omitted']` with the preview dimensions carried through; that `generated` is `false` and
no `Image model:` caption can be rendered; that a resolved image embeds as a
`data:image/webp` figure; that the preview route never appears in the rendered HTML; that
an off-route or cross-origin pointer is refused without a fetch; and that resolution
succeeds with no auth context.
