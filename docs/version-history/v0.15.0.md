## Purpose

Claude exports can now carry the reasoning summaries and tool calls that sit between a
prompt and its answer. Until this release `thinking` and `tool_result` blocks were dropped
outright and `tool_use` became an omission marker, so an agentic conversation exported as
a series of answers with no account of how they were reached.

## What the payload actually carries

Established by running `diagnostics/claude-thinking-probe.js` against a live conversation
with eight thinking blocks and eight tool calls on 2026-09-18. The probe reports structure
only. Two findings shaped the feature:

**Claude does not send the raw reasoning text.** Every thinking block came back with
`thinking_hidden: true` and `thinking` as a zero-length string. What the payload does carry
is `summaries[].summary` — the step lines Claude's own UI shows — plus `start_timestamp`
and `stop_timestamp`, which is where "Thought for 56s" comes from. No export can contain
the full reasoning, because it never leaves Claude's server. The exporter still reads
`thinking` and renders it when non-empty, so a payload that does carry it is not discarded.

**Tool calls are fully present.** `tool_use` carries `name`, `integration_name` (the
connector, e.g. `Consensus`), `input`, `message` and timestamps. `tool_result` carries a
`content[]` array of text parts — up to ~20 KB each in the sampled conversation — plus
`is_error` and a `display_content.json_block` that duplicates the same payload formatted
for Claude's UI. The duplicate is deliberately **not** read: carrying both would roughly
double an export for no added information.

No identifier, reasoning text, tool input or tool output from that run was recorded here.

## User-visible changes

**Off by default, one checkbox to include.** A new export preference, *Include Claude
thinking and tool calls (collapsed in the file)*, defaults to unticked. Reasoning and tool
detail is the most sensitive material in a conversation and exports get shared, so only a
literal `true` in stored preferences enables it — a preference saved before this release
cannot opt anyone in.

**Collapsed in the HTML.** Each block renders as a `<details>` element, closed on load:
`Thought for 56s` over the summary list, and `Tool result · Consensus · consensus_search`
over the returned text. A tool call itself shows its name, connector and input inline,
because which tool ran and what it was asked is the part worth seeing at a glance; the
result is what hides. `<details>` needs no JavaScript, so the file still works with scripts
disabled and the restrictive CSP is untouched.

**When excluded, the file says so once.** A conversation with tool calls holds more
supporting blocks than answers, so a skipped block leaves no marker. The header carries one
neutral line naming the count and the setting that keeps them, matching how unexported
branches are already reported.

## Also fixed

The image preferences were gated to ChatGPT in the options dialog, so a Claude user could
not reach *Exclude all images* or the per-image chooser even though v0.15.0's predecessor
made the export path itself provider-neutral. The fieldset now shows for both providers,
which is what v0.14.0's release note already claimed.

## Behaviour deliberately unchanged

- Local statistics still count text and code blocks only. Tool output does not inflate the
  word count, and an export with reasoning included reports the same figures as one without.
- A tool's `id` / `tool_use_id` is provider plumbing and is never rendered.
- ChatGPT exports are untouched. The preference is Claude-only in effect, because ChatGPT
  reasoning does not reach this exporter in the same shape.

## Validation

| Check | Result |
|---|---|
| `npm run check` | Passes, with the new `claude-reasoning-conversation.json` fixture |
| `node --check dist/chatgpt-chats-exporter.user.js` | Passes |
| Root and `dist` artifacts byte-identical | Yes |
| Live Claude export of a conversation with reasoning and tool calls | **Pending product-owner testing** |

The fixture reproduces the live shape, including a withheld-reasoning block, a populated
one, a successful tool call and a failing one. Coverage asserts the block order
`['thinking', 'tool_use', 'tool_result', 'text']`; that the withheld block has empty text,
two summaries and a 56-second duration; that capturing these blocks does not inflate the
omitted-block warning; that an export with the preference off renders no reasoning markup
and leaks neither the tool input nor the tool output into the file; that an export with it
on shows the duration, the summary lines, the connector-qualified tool label and the
result; that `display_content` is not carried; and that a tool id never appears.
