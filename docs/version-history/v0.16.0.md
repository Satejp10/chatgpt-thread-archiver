## Purpose

Export ChatGPT temporary chats (`chatgpt.com/?temporary-chat=true`) and Claude incognito
chats (`claude.ai/new?incognito`).

## How the conversation is found

The exporter normally reads the conversation id from the address bar. Neither temporary
route puts one there, so the id comes from the page's own same-origin requests to the
conversation API, read through Resource Timing and a `PerformanceObserver` (the timing
buffer stops recording at its limit; an observer does not).

- **ChatGPT:** the most recent `/backend-api/conversation/<id>` request.
- **Claude:** only `…/chat_conversations/<id>/completion` or `retry_completion` — the
  request that sent the message. Sidebar and prefetch requests on a Claude page can name
  other conversations, so a plain fetch is not trusted.
- **Only requests after entering the temporary route count.** A user who opens a
  temporary chat from a normal one without reloading cannot export the earlier chat.

Until the first reply exists there is no id, and the **Export HTML** button stays hidden.
It appears on its own once the request is seen. The fetch, rendering and privacy handling
after that point are unchanged.

`@match` gains two query-specific lines. It deliberately does not widen to the whole
host.

## Known risk

Shipped without a live check, at the product owner's call. Nothing public confirms that
either provider's conversation API returns a chat kept out of history. If it does not,
the export fails with the existing error message and writes nothing.
`diagnostics/temporary-chat-probe.js` settles it in one console paste.
