## Purpose

Two faults found in the product owner's live test of v0.16.0.

**A new chat got no button until a reload.** The script only loaded on chat addresses.
Starting a chat from the home page changes the address inside the app, which never loads
a userscript, so the button stayed missing until a refresh. The script now loads on all of
`chatgpt.com` and `claude.ai`, and the route check alone decides where the button shows. It
still shows only once a conversation exists, and never in ChatGPT's `codex`, `scheduled`
or `library` sections (owner's call). Claude had the same fault (`/new` becomes
`/chat/<id>`) and gets the same fix.

**Claude incognito showed no button.** ChatGPT temporary chats worked. The likeliest cause:
the request window was keyed on the full address, so if Claude rewrote the address after
the first message (for example `?incognito=` to `?incognito`), the exporter treated it as
a new chat and discarded the request naming the chat. The window is now keyed on the route
type, not the address. Loading the script on the whole host also covers entering
incognito mode from inside the app.

The owner's live test after release passed: new chats get the button without a reload, and Claude incognito exports. Which of the two changes fixed incognito was not isolated. `diagnostics/claude-incognito-route-probe.js` reports
which request names the chat if the button is still missing.
