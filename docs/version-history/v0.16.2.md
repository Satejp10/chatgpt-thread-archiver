## Purpose

A code review of v0.16.1 and two faults the product owner found in live use.

**From the review (confirmed by simulation before fixing):**

- **Wrong chat exported (ChatGPT).** `endpointCandidates()` mapped the page's request
  hints back to real paths, but another chat's request redacts to the same hint and was
  mapped back to that chat's path and tried first. Opening or exporting chat A, then
  switching to chat B without a reload, exported A. Only paths for the open chat's ID
  are used now.
- **Text lost to emphasis.** `inlineFormatting()` turned `MAX_RETRY_COUNT` into
  `MAX<em>RETRY</em>COUNT`, inside code spans and links too. Emphasis now needs a word
  boundary on the outside and no space on the inside, and code spans are literal.
- **Claude image choice ignored.** The dialog showed the image options to Claude since
  v0.15.0, but the click handler kept the stored value for Claude.
- **Errors hidden.** Every non-error status started its own 6-second hide timer, so an
  earlier status hid a later error. One timer, cleared on every update.
- **Shared images per branch.** All-branches exports fetched an image in a shared message
  once per branch, counted every copy, and listed every copy in the chooser. One cache
  across branches, chooser entries keyed by message and block, totals counted from the
  messages the file shows. A ChatGPT file request that returns the image directly is read
  instead of requested twice.

**From the owner:**

- **ChatGPT dialog had no visible checkboxes or radio buttons**, though they worked. The
  page's CSS reached the dialog. The exporter's button, panel and dialogs now live in an
  open shadow root on a `<chatgpt-thread-archiver>` host whose inline style resets
  inherited properties except `color-scheme`, so the dialog still follows the site theme.
  The exact ChatGPT rule is unknown: its stylesheets could not be fetched from the build
  environment (Cloudflare 403; the logged-out page uses StyleX). Isolation covers any rule.
- **Some Claude exports fail with "could not find this conversation" (404).** Claude
  merged chat and Cowork on 2026-09-16, and Cowork tasks now open from the same list as
  chats. A third-party report (Aug 2026) says Cowork sessions use `cse_` IDs and that
  `chat_conversations/<cse_id>` returns 404. Not confirmed for this account. The exporter
  now retries in the account's other organizations (a second known cause of a 404) and,
  when every organization answers 404, reports the ID format, the organizations checked
  and the redacted shapes of the page's own API requests for the chat.

## Privacy

The 404 report carries path shapes only. The conversation ID becomes `<this-chat>`, other
identifiers become `<id>` (or `<prefix_id>` for a short type prefix such as `cse_`), and
query values are dropped. The organization list request is same-origin, GET, cookie-only,
and its IDs are validated before use.

## Limitations and decision

Conversations Claude serves outside the chat API still cannot be exported. The next
failing export's error text names the endpoint Claude's page used, which is what support
needs. Separately reported, not addressed here: Claude exports show a model on only one
message.
