## Purpose

The product owner's live test of v0.16.3 (2026-10-29), with a screenshot of the 404 report,
a screenshot of a Claude chat, and the export of a chat whose "hi" was retried with three
models.

**A Claude chat still fails with a 404.** The report read: chat API 404 in both
organizations, `Retries: consistency=strong (HTTP 404)`, one page request naming the chat
(`…/chat_conversations/<this-chat>/composer_notices (HTTP 200)`) and, among the page's other
requests, `/claudeai-rpc/<id>/<id> (HTTP 200)` and `/v1/code/sessions/<cse_id> (HTTP 200)`.
Claude's page never asked the chat API for the message tree. The notes of Claude-QoL, a
third-party extension (`docs/bard-rework.md`, and `scripts/bard/README.md` in its
`claude-ext-common` library), describe Claude's new layout: chats load from a Connect RPC
service at `/claudeai-rpc/anthropic.bard.api.v1alpha.ConversationService/`, through
`StreamTimeline`. The same service has a unary `ReadConversation` that returns the whole
message tree, and `ReadConversationHistory` for older pages. It accepts JSON and checks the
request's origin, so it can be called only from the page.

v0.16.4:

- after the chat API refuses a chat in every organization and every retry, asks
  `ReadConversation` in the same organizations (at most six), and pages back with
  `ReadConversationHistory` when the answer has an older-history cursor;
- converts the answer into the chat API's shape, so the existing normalizer, branch
  selection and renderer handle it: every version of each message, text, thinking, tool
  calls with their inputs and results, code, and images. Other cards are marked omitted;
- shows the model that answered on a reply the service marks as answered by a different
  model than the one asked for (`turnModelFallback.servedModel`);
- warns in the header when the service stops before the start of the chat;
- keeps the service and method names in the 404 report instead of `<id>/<id>`, and lists
  each `ReadConversation` answer with its status and error code.

A chat the chat API serves is unaffected: it still takes one request.

**Replies still name no model.** The owner's export of the retried "hi" chat has three
versions, the header `Chat model: claude-opus-5-5 (Claude’s data names no model for
individual replies)`, and `Model: unknown / not found` on every reply. So v0.16.3's
reply-model scan found no model-named field on any reply. Per Claude-QoL's schema notes,
the new service's messages carry no model either, except `turnModelFallback`. No change is
possible beyond that case.

**Claude no longer shows ‹ 1/3 › on retried messages.** The owner's screenshot shows retry,
edit and copy on the prompt and no version arrows. Per Claude-QoL
(`content/main/branch-arrows.js`, issue #84), Claude shows them only for messages whose
`siblings_viewable` is true, which is the case for versions made before the account moved
to the new layout. The stated reason is that every version shares one file workspace
(`/mnt/user-data`) that does not roll back. The Claude app changelog at
claude.com/docs/cowork/changelog has no entry about it (read for August to October 2026).
The exporter needs no change: the data still holds every version, and the owner's export
shows `Branches: 3 available`.

## Privacy

`ReadConversation` and `ReadConversationHistory` are same-origin POSTs with the session
cookie, sent only after the chat API refused the chat. The body holds the conversation ID
and, for history, the cursor the service returned (at most 4,096 characters). The
organization header uses the same validated organization IDs as the chat API requests. The
report adds call names and error codes, which are short lowercase words checked against a
pattern; identifiers stay redacted. A service or method name is kept only on a
`/claudeai-rpc/` path and only when it has the shape of a dotted service name or a
capitalized method name. Model values are kept only when they pass a short identifier
check.

## Limitations

The service's JSON format and field names come from third-party notes, not from Anthropic,
and were tested only against a stand-in. If the service refuses the chat, the new report
lines say how. Replies keep `Model: unknown / not found` unless Claude switched the model
itself.
