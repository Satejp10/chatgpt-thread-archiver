## Purpose

The product owner asked for two features:

1. A **Quick export** button beside the export button that skips the menu and uses the
   last settings.
2. A **copy** button in the exported HTML that copies the whole chat as formatted text,
   so that pasting into an app such as Obsidian keeps headings, lists and tables, without
   images, with options to include thinking, tool calls and other available content.

## User-visible changes

See `CHANGELOG.md` [0.17.0]. In short:

- **Quick export.** The floating control is now one pill with two buttons:
  `⚡ Quick export | Export HTML…`. The menu button stays at the right edge where it was.
  Quick export uses the saved menu choices, or the menu's defaults before any are saved.
  Its tooltip and the status message name the settings used. A saved **Choose images**
  still opens the image list. The menu says its choices are saved and reused.
- **Copy chat.** A split button at the top of the exported file: **Copy chat** copies;
  the arrow opens the choices (names, thinking, tool calls and results, timestamps, model
  names, chat title, export details, notes for left-out content, hidden messages). A
  choice is shown only when the chat has that content. Thinking and tool calls the export
  left out are greyed out with "not in this export". Choices persist in `localStorage`
  (`chatgpt-thread-archiver-copy-options`). Only the versions on screen are copied.
- **Per-message Copy** uses the same format and choices.

## How the copy works

The export keeps each message's own Markdown lines (headings, list markers, table rows)
as text and turns only bold, italics, inline code and code fences into tags. The copy
script walks the page and turns those tags back, so the Markdown it builds matches what
the provider sent. It then puts two formats on the clipboard:

- `text/plain`: the Markdown;
- `text/html`: HTML built from that Markdown by `copyMarkdownToHtml` (headings, nested
  and task lists, tables with alignment, quotes, fenced code, links, emphasis). Everything
  is escaped; only `http(s)` and `mailto` links become links; images keep only their
  description.

Obsidian converts pasted HTML to Markdown by default ("Auto convert HTML", Settings →
Editor) and pastes the plain text with Ctrl/Cmd+Shift+V. Source for the default: a
community settings reference and forum posts, not Obsidian's own docs. Both formats are
correct, so it does not matter which one an app takes.

The write uses the `copy` event (it sets both formats in every browser, `file://`
included), then the Clipboard API with `ClipboardItem`, then `writeText` with Markdown
only. The status line says when only plain text could be copied.

`copyMarkdownToHtml` and `exportCopyRuntime` are serialized into the file with
`toString()`, so they are self-contained. The file still has one inline script and the
same CSP; the script carries no chat text.

## Privacy

No change to requests. The copy script makes no requests and reads only the file's DOM.
Copy choices are stored in the browser's `localStorage`, like the theme.

## Limitations

- The exported page itself still shows Markdown headings, lists and tables as text (it
  always has); only the copy turns them into structure.
- Inline LaTeX and footnotes are copied as written, not converted.
- A message the export marks as hidden by the provider is copied only when that choice
  is ticked.
