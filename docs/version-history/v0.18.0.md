## Purpose

The product owner asked for a token estimator next to the existing word and character
counts, and chose the "smart estimate" for ChatGPT from a comparison of three options:
characters ÷ 4 (3–25% off on English, about 70% off on Chinese and Japanese), the smart
estimate, and bundling OpenAI's real tokenizer (exact, but about 2.4 MB, ten times the
script). Claude is out of scope: its tokenizer is unpublished, and Anthropic's counting
endpoint needs an API key and would send the chat out, which the project's rules forbid.

## User-visible changes

- A ChatGPT export's stats line ends with `about N tokens (local estimate)`. Holding the
  pointer over it explains that it follows the tokenizer ChatGPT's models have used since
  GPT-4o and leaves out hidden reasoning, system instructions and uploaded files.
- The message after the download reads `… words, … characters and about N tokens counted
  locally.`
- The number is rounded to three significant figures (exact below 1,000).
- Claude exports are unchanged.

## How the estimate works

`src/token-estimate.mjs`, with no vocabulary and no requests:

1. It splits the text with o200k_base's own pre-tokenizer pattern, copied from OpenAI's
   tiktoken. No token crosses two pieces, so this step is exact. Splitting 9,292
   paragraphs (7.5 million characters in 30 languages, plus code) and counting each piece
   with the real tokenizer gave exactly the tokenizer's own totals.
2. Each piece gets a family (letters by script, case and leading character; ASCII and
   other digits; spaces; line breaks; punctuation) and a length. `O200K_TABLE` gives the
   average token count measured for that family and length, or a per-character rate past
   the measured lengths. One to three ASCII digits are always exactly one token.
3. A paragraph where `{ } ; = < > [ ]` or `()` are common is treated as code and uses its
   own families.
4. Other paragraphs are checked for very common words of 17 languages, kana for Japanese,
   and Han letters for Chinese. A clear winner's factors scale the paragraph's word pieces.
   A paragraph with accented Latin letters, no English hint words and no clear language
   gets a general factor for other Latin-script languages.

`tools/fit-token-estimate.mjs` generates the table against the real tokenizer
(`gpt-tokenizer` 4.1.0, installed only for the run). The shipped table was fitted on
Wikipedia articles on seven topics in 25 languages, this repository's Markdown and
JavaScript, and some Python standard-library files. No corpus text is committed; the table
holds averages only: 75 families and factors for 20 languages. The userscript grows by
about 21 KB, from 229,798 to 251,010 bytes. Estimating 2 MB of text takes about 0.7 s in
Node.

## Accuracy

Cross-validated by topic: the table was fitted on six topics and tested on the seventh,
seven times over, so no test article was seen in fitting. Repository docs and code were
split by file. "Whole text" is the error over all test samples together; "per sample" is
the typical (median) and 90th-percentile error of a 300–3,000 character sample, about the
size of one chat message.

| Text | Whole text | Per sample (median / 90th) | Characters ÷ 4, whole text |
|---|---|---|---|
| English docs (repository Markdown) | +0.9% | 1.8% / 5% | +11.9% |
| English Wikipedia | −0.7% | 3.4% / 8% | +23.6% |
| A real Claude chat (English, owner's export) | −2.8% | — | +7.2% |
| JavaScript | +2.9% | 3.3% / 8% | −0.3% |
| Python | +0.8% | 2.5% / 7% | +2.4% |
| es, fr, de, it, pt, nl, pl, tr, vi, id | −0.5% to +2.9% | 3.1–6.6% / 7–14% | −20.5% to +11.1% |
| ru, uk, el, ar, fa, he, hi, mr, bn, ta, th, zh, ja, ko | −0.9% to +1.1% | 2.8–10.2% / 5–16% | −71.6% to −8.6% |
| Untuned: Czech, Hungarian, Swedish, Romanian, Finnish | −5.0%, −5.5%, −7.7%, −12.0%, −23.2% | 5.2–23.5% / 13–27% | −28.4% to −5.8% |

The table that ships was then fitted on all seven topics. On the 20 original texts in
`fixtures/token-estimate-samples.json` (never used in fitting, about 100 tokens each) it is
1.7% low on English, 4.5% high on code and 5.3% low on other languages; the worst single
texts are Portuguese (13.8% low) and Italian (12.0% low), both dense with rare scientific
words. The checks require each English sample within 10%, code within 12% and other
languages within 18%, and each group's total within 5–8%.

## Privacy

The estimate is computed in the page from the text already being exported. It makes no
request, stores nothing, and reads no provider data. `test.mjs` checks the module for
network and storage calls.

## Limitations

- The estimate covers the exported text. It is not ChatGPT's token or context-window use.
- Languages without hints or training data can be 5–20% low, more for heavily inflected
  ones such as Finnish.
- Older chats answered by GPT-4 or GPT-3.5 used a different tokenizer (cl100k_base); the
  estimate still follows o200k_base.
- Each new tokenizer, or a change to ChatGPT's, needs a new table.
