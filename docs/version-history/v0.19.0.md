## Purpose

The product owner asked for two things in the exported file: every message should fold
like a thinking block, and the top right of the file should show the share of the context
window the chat uses, against a 1M-token window by default with other sizes (256K, 500K
and so on) to pick from. The gauge needs a figure for Claude chats too, so this version
builds the Claude estimate that the v0.18.0 research described but left out.

## User-visible changes

- Each message's header (name, model, time) is a disclosure: a click or Enter folds the
  message to one line that shows the start of its text. ChatGPT tool messages start
  folded, like Claude's tool blocks; every other message starts open. It works without
  scripts. The **Copy** button sits outside the header, so copying never folds a message,
  and copying a folded message copies all of it.
- A gauge at the top right of the header reads `Context used`, a percentage, a bar, and
  `≈N of [1M] tokens · local estimate`. The list offers 32K, 128K, 200K, 256K, 400K, 500K
  and 1M. The file is written for 1M, so it reads correctly with scripts off; the page
  script redraws it for another size and keeps the choice in this browser's storage, like
  the theme. The bar turns amber from 80% and red from 100%. The tooltip lists what was
  added up and what was not.
- `j`/`k` prompt navigation ignores key presses while the window list has focus.
- The stats line and the download message are unchanged.

## How the estimate works

`src/context-estimate.mjs` takes the chat's current branch, as normalized for the export,
and makes no request. The gauge always counts the current branch, because only one branch
is ever in the model's context.

- **ChatGPT:** the o200k estimate of the messages' text (v0.18.0), joined as the word count
  joins it, so it equals the stats line's figure for a current-branch export. ChatGPT's
  data carries no system instructions, memory or hidden reasoning, so none are counted;
  images and files are not counted either.
- **Claude:** the sum of five parts.

| Part | Rule | Source |
|---|---|---|
| Messages | o200k estimate × 1.4 | A third-party tokenizer test (2026-10-28) counted a 558-word English passage at 639 o200k tokens and 896 tokens for Claude models from Opus 4.7 on, about 1.4×; the same test found Russian, Chinese and Arabic changed less ([nesyona](https://nesyona.com/research/ai-tokenizer-inflation-2026/)). |
| Tool calls and results | Tool name and input JSON, and result text: o200k estimate × 1.4 | As above. |
| Thinking | Seconds between each thinking step's start and stop times × 100 | Opus 5.5 produced thinking at a median 96 tokens a second (84–106) over 29 API calls in a measured session; the whole session's total came within 1%. Measured through the API, not in the app. Anthropic's [extended-thinking docs](https://platform.claude.com/docs/en/build-with-claude/extended-thinking) say Opus 4.5 and models numbered 4.6 and higher keep earlier turns' thinking in context; the app is assumed to do the same. |
| Instructions | 8,700 tokens | The [published Opus 5.5 app prompt](https://platform.claude.com/docs/en/release-notes/system-prompts/claude-opus-5-5) of 2026-10-27 is 6,213 o200k tokens, × 1.4. Tool descriptions, connectors, preferences, memory and project knowledge come on top and are not published. |
| Images | ceil(w / 28) × ceil(h / 28), long edge scaled to 2,576 px, at most 4,784 per image | Anthropic's [vision docs](https://platform.claude.com/docs/en/build-with-claude/vision) for models from Claude 4.7 on. The size is the preview size in Claude's data; an image without one is reported, not guessed. |

A thinking step without times is reported in the tooltip and counts as zero. The Claude
Help Center gives Opus 5.5 a [1M-token context in chat](https://support.claude.com/en/articles/8606394),
which is why 1M is a sensible default, and says that with code execution on, Claude
[summarizes earlier messages](https://support.claude.com/en/articles/11647753) near the
limit, so on very long chats the sum overstates what Claude still holds.

For the owner's Huxley test chat (Opus 5.5, v0.18.0 research) the same parts came to about
26,000 tokens, about 2.6% of 1M, plus the unpublished tool descriptions.

## Privacy

Nothing new leaves the browser. The estimate uses the chat data the exporter already
fetched and writes one number and its breakdown into the file. The file stores only the
picked window size, under `chatgpt-thread-archiver-context-window`. `test.mjs` checks the
module for network and storage calls.

## Limitations

- A local estimate, not ChatGPT's or Claude's own number. For ChatGPT it is a floor: the
  real context also holds instructions, memory and files.
- Claude's 1.4 factor comes from one English test; other languages are likely lower.
- Thinking speed may differ in the app and between models (Sonnet and Haiku were not
  measured).
- Claude's instructions figure is for Opus 5.5's published prompt and needs updating when
  Anthropic republishes it.
- Older ChatGPT chats answered by GPT-4 or GPT-3.5 used another tokenizer (cl100k_base).
